# Todora 0.11.1 review

Reviewed on 27 September 2026 against `3123925` (`main` and remote `main` matched). This review is for deciding what to fix and build next. The packaged version reviewed was 0.11.1; the fixes below are follow-up source changes.

Todora has a sound foundation for a small racing game: feature plugins have clear owners, the physics runs at a fixed step, the server reuses the real lap judge, and the tests exercise all forty circuits. The main weaknesses are persistence at shutdown, coverage of UI state transitions, oversized layouts, and the amount of rendering code pulled into the server build. A wholesale directory rewrite would add churn without addressing those weaknesses.

**Structure and changes made**

Keep the existing feature organisation: `car/`, `track/`, `ghost/`, `settings/`, `online/` and `multiplayer/`, with small standalone plugins at the root. Keep Blender sources in `art/`, runtime assets in `assets/`, build tools in `tools/`, and the HTTP service in `server/`.

- Moved the large track regression suite and its test-only tolerances into `src/track/tests.rs`. The main module now concentrates on track queries, construction and switching. All moved test bodies match the original after formatting. The production geometry, fingerprints and physics remain unchanged.
- Added `src/persistence.rs` for the two stores with the same save-ordering and shutdown problem: settings and achievements. It allows one write per store at a time, saves after a bounded delay from the first pending change, retries failed writes, and flushes on normal exit. It retains the existing temporary-file-and-rename approach and file formats.
- Updated Linux CI to lint and test the entire workspace, including the server, and run the Python tool tests. Updated the README commands to match. The validation below is local; the expanded workflow also runs on pushes and pull requests.

| Finding | Cause and correction | Evidence |
| --- | --- | --- |
| Choices could disappear when quitting immediately after a change. | The one-second debounce had no exit flush; detached writers could also outlive the process. Settings now consume `AppExit` in `Last`, finish any previous write and save the latest snapshot. | Regression tests cover quitting before the delay and exiting with a previous write pending. |
| Achievement saving could be postponed throughout a purple sector. | The advancing lap timer repeatedly called `announce` for an already-earned achievement, marking the resource changed every frame. The existing debounce restarted each time. Repeated announcements now leave the resource untouched; the shared writer also tolerates continuous changes. | A regression test advances the timer after earning purple and checks that achievements stay unchanged; it fails against the original system. |
| FPS appeared over the title and could remain visible during replay/photo mode. | The FPS system and the general HUD system both wrote the same `Visibility`. The FPS toggle now changes `Node.display`; HUD visibility owns the menu/replay state. | Regression test (fails against the original system) plus before/after title captures. |
| Server regressions could pass the normal CI checks. | Cargo commands from the workspace root selected the game package without `--workspace`. The workflow now includes both packages. | Local workspace tests and all-feature Clippy. |

The save guarantee covers normal app exits and completed file renames. It does not promise recovery of the most recent change after a force-kill or durability through power loss. Multiple game processes writing the same save directory are still unsupported by this writer.

**Validation**

The unmodified baseline passed 321 game tests and 15 server tests. After the changes, 326 game tests and 15 server tests pass, with 12 optional game tests ignored. The five added regressions cover save ordering, immediate exit, write retry, repeated purple-sector announcements and FPS visibility. The five Python tool tests pass. Formatting and workspace Clippy with all features pass.

Rendered checks cover chase, bonnet and cockpit cameras, title, circuit browser, the empty replay screen, German settings and leaderboard, and a reduced-resolution world with high-contrast HUD and TV margin. Logs and PNGs are in the local, ignored `dist/review/` directory. These are real Apple Silicon/Metal launches, not mocked render tests. Their FPS readouts are not controlled performance benchmarks.

No live server was changed. This pass does not certify a Linux hardware run, Game Center matchmaking, controller rumble, audible radio/engine quality, or a long driving session. CI's all-feature compile checks are broader than the default-feature runtime tests.

**Visual direction**

Preserve the low-poly character, pale blue/orange car, graphite panels and lime accent. The circuit browser already has a clear hierarchy and cohesive selection treatment; use it as the reference for the other screens.

1. **Give the road more room.** The driving view has six competing information areas, with permanently visible controls and a large timing block. Offer a compact HUD: speed, current lap and delta first; last/best times and control help on demand. Make the mini-map's visible backing circular, matching the map itself. Keep the full HUD available.
2. **Integrate the cockpit.** The dashboard and wheel are attractive foundations, but the generic speed/G-meter panel duplicates their space. Put speed/gear information on the dash and use a smaller timing overlay in this camera. Test steering-wheel visibility, road sightlines and near-plane clipping while the car pitches and rolls.
3. **Give circuits recognisable surroundings.** The captured driving views show broad areas of similar grass and repeated tree silhouettes. Build a few coherent environment families—woodland, alpine, coastal, desert and city—with distinct horizon silhouettes, vegetation colours and a small number of landmarks. Keep braking markers and road edges visually dominant.
4. **Improve contact and depth.** Trial a soft contact shadow beneath the car, subtle verge colour variation and baked occlusion on scenery. Keep the existing readable road material and compare the added GPU cost on low-end Linux hardware before adopting global dynamic shadows.
5. **Compose the title shot.** The wide orbit exposes the rectangular terrain boundary, and the subtitle loses contrast against the scenery. Frame a recognisable corner or the car more closely, keep the terrain edge out of shot, and use a restrained gradient behind the text. Respect reduced-motion settings.

The README also mixes current controls with historical implementation notes and older dimensions. Keep its download/build/controls entry points short and move historical details into dedicated docs as a separate documentation pass.

Suggested order: finish responsive overlays and transition coverage, simplify the HUD and cockpit presentation, then build one polished environment family and measure it before applying the treatment to all forty circuits.
